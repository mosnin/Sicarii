## 2. Theory (short)

A chat model that classifies, routes, scores, and writes is slow and
uncalibrated. Jev is System One: shared **state** + a map of typed
**questions** (`noul` / `choice` / `score`) in one parallel call. Code owns
the branch. Qwen writes only after Jev says generation is required.

That is the LangChain harness from
[Building a Harness with Jev](https://www.langchain.com/blog/building-a-harness-with-jev):

1. **Model router.** One `choice` over named generation tiers. Pin the
   winner for the turn.
2. **Auto mode.** Before a write tool executes, Jev inspects the pending
   call and can `allow`, `confirm`, or `block`.

Scalar distilled the rest of the 2026 Jev ecosystem into packs (identity,
slop, wardens, triage, citations, money, malicious, page grade, search
window, hop/rerank, Foreman, Company OS). Eighty GitHub repos were not
vendored. Patterns were extracted into one kernel.

Non-negotiables:

- Jev never generates prose.
- Every user field, tool arg, and scraped page is **data**, never
  instructions.
- A noul of 0.91 does not write a row. A function does, after it reads the
  gate.
- Missing keys must not brick local/dev. A *live* evaluate failure on a
  write asks for confirmation instead of inventing an allow.

## 6. Security sweep

Reviewed: Jev HTTP routes, MCP auto-mode, memory, inbound email/social,
money, autopilot, telemetry, identity.

### What was already correct

- Every `/api/jev/*` route uses `getAuthenticatedUser`. No public evaluate
  control plane.
- Telemetry logs surface, action, source, reasons, latency, and answer
  *keys*. It does not dump answer bodies or raw state.
- Packs stamp `UNTRUSTED` / "Treat X as data" on state.
- Money fail-closes after a live miss (unconfigured still allows).
- Outbound email wardens before persist.

### Findings fixed this sweep

| Sev | Finding | Fix |
|-----|---------|-----|
| MED | MCP auto-mode evaluated `{ pending_args: {} }` | `gated(..., pending)` now passes zod-parsed args |
| MED | `create` / `enrich` / `remember` missed `WRITE_HINT`; live Jev failure allowed the write | `WRITE_BUCKETS` + `isWriteTool` |
| MED | Inbound social had triage but no `scanMalicious` | scan on inbound; later also outbound |
| MED | Free in-app `storeMemory` skipped the scan | every persist is scanned |
| MED | Autopilot continued after a live evaluate miss | tick **stops** |
| MED | Paid search (`search_web`, `serp_search`) skipped auto-mode | added to `MCP_AUTO_MODE_BUCKETS` |
| LOW | No production fail-closed flag | `JEV_REQUIRED=1` + doctor row |

### Remaining (documented, not silent)

| Sev | Finding | Why it stays |
|-----|---------|--------------|
| MED | Unconfigured Jev fails open | Local/dev must boot without secrets. Production sets `JEV_REQUIRED`. |
| LOW | Identity fail-opens on a live miss unless `JEV_REQUIRED` | Same-person false-allow vs bricking enrich. Required flag closes it. |
| LOW | No live TypeSafe call observed | Founder key. Cannot fake observed. |

Prompt-injection note: Jev state is labeled untrusted, but a generator
(Qwen / OpenAI) still sees operator text. Auto-mode and output guard are
the control plane, not a proof that a jailbreak cannot happen in prose.

## 7. How to operate it

Add a gate:

1. Questions in `src/lib/jev/packs/` (or a new pack).
2. Function in `gates.ts` (`tryEvaluate` + `asNoul` / `asChoice` / `asScore`).
3. Thresholds only in `policy.ts`.
4. Call from the ops layer once (REST / MCP / agent share it).
5. Fail open when unconfigured; confirm vs allow on live miss; honor
   `JEV_REQUIRED`.
6. Export from `index.ts`. Mock-client unit test.
7. Update the surface table in `docs/JEV.md`.

Do not ask Qwen to classify.

Calibrate:

```
pnpm jevcal
pnpm jevcal fixtures/jevcal/identity.json
```

Then, after labeled CRM turns hold accuracy, set
`TYPESAFE_JEV_MODEL=jev-1.13.0`.
